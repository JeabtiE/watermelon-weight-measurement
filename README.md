# Watermelon Size & Weight Grading System

ระบบวัดขนาดและประมาณน้ำหนักแตงโมแบบไม่สัมผัส (non-contact) โดยใช้กล้องเว็บแคมร่วมกับ
OpenCV สำหรับประมวลผลภาพ และ Qt สำหรับส่วนติดต่อผู้ใช้ (GUI)

> หมายเหตุ: README นี้เขียนขึ้นจากการอ่านซอร์สโค้ดในแต่ละโฟลเดอร์ย่อยที่ส่งมา
> ส่วนที่เป็นการตีความ/สันนิษฐาน (ไม่ได้ระบุไว้ในโค้ดตรง ๆ) จะระบุกำกับไว้ชัดเจน

## ภาพรวม

โปรแกรมนี้ใช้กล้องจับภาพแตงโม แล้วประมวลผลภาพเพื่อ:

1. หาโครงร่าง (contour) ของแตงโมในเฟรม
2. วัดความกว้าง/ความสูงเป็นพิกเซล แล้วแปลงเป็นเซนติเมตรด้วยอัตราส่วน `pixel_per_cm`
3. ประมาณน้ำหนักด้วยสูตรเชิงประจักษ์แบบทรงรี (ellipsoid approximation)
4. จัดเกรดคุณภาพ A / B / C ตามน้ำหนัก
5. บันทึกผล (บางเวอร์ชัน) ลงฐานข้อมูล SQLite เพื่อดูสรุปย้อนหลัง/ส่งออกได้

## โครงสร้างโปรเจกต์ (แต่ละโฟลเดอร์คืออะไร)

โปรเจกต์นี้พัฒนาเป็นหลายเวอร์ชัน/หลายโมดูลที่แยกกันทดลอง แต่ละโฟลเดอร์คือขั้นหนึ่งของการพัฒนา:

| โฟลเดอร์ | ลักษณะ | จุดเด่น |
|---|---|---|
| `compro/` | โปรแกรม console ต้นแบบ (ไม่มี GUI) | ทดสอบอัลกอริทึมวัดขนาด/น้ำหนักตัวแรกสุด ใช้ `pixel_per_cm` คงที่ (25.5) |
| `GUI/` | แอป Qt Widgets ตัวแรกที่มีหน้าจอ | มีหน้า Home, MainWindow (วัดจริง), CalibrationWindow (ปรับค่าสเกล) |
| `GUI_ArUco/` | แอป Qt เหมือน `GUI/` | ปรับให้ใช้ ArUco marker ช่วยคำนวณ homography สำหรับปรับมุมกล้อง/สเกล แทนค่าคงที่ |
| `GUI_calibrate/` | แอป Qt เริ่มที่หน้า CalibrationWindow | ปรับเทียบสเกล (`pixel_per_cm`) แบบอัตโนมัติ โดยใช้ **บัตร (บัตรประชาชน/บัตรเครดิต ขนาดมาตรฐาน 8.56 ซม.)** เป็นวัตถุอ้างอิงแทนการตั้งค่าคงที่หรือ ArUco |
| `GUI_card/` | แอป Qt เริ่มที่หน้า CalibrationWindow → MainWindow | เวอร์ชันที่เพิ่มการจัดเกรด A/B/C และบันทึกผลลง SQLite (`watermelon.db`) |

โฟลเดอร์ `opencv/` ที่อยู่ในบางซิป **ไม่ใช่โค้ดของโปรเจกต์** แต่เป็นซอร์สโค้ด OpenCV ทั้งชุดที่ build ไว้ใช้เอง
(เพราะ `CMakeLists.txt` อ้างอิง `OpenCV_DIR` เป็น path ตายตัว `C:/project_compro/opencv/build`)
และโฟลเดอร์ `build/`, `.qtcreator/`, `.vscode/` เป็นไฟล์ที่ IDE/CMake สร้างขึ้นอัตโนมัติ ไม่ควร commit

## ขั้นตอนการทำงาน (Pipeline)

ทุกเวอร์ชันใช้แนวคิดเดียวกัน ต่างกันที่รายละเอียดการปรับเทียบสเกลและ feature เสริม:

1. **จับภาพ**: เปิดกล้องด้วย `cv::VideoCapture(0, cv::CAP_DSHOW)` (บังคับใช้ DirectShow backend บน Windows กันปัญหากล้องเปิดไม่ติด/แครช)
2. **Preprocessing**: แปลงเป็นภาพขาวดำ (grayscale) → `GaussianBlur` ลด noise → หาขอบ/แยกพื้นหลัง ด้วย `adaptiveThreshold` (เวอร์ชัน console/GUI) หรือ `Canny` (เวอร์ชัน calibrate) → `morphologyEx` (MORPH_CLOSE) เพื่อปิดรูให้ contour สมบูรณ์
3. **หา Contour**: `findContours` แล้วกรองด้วยพื้นที่ขั้นต่ำ (area threshold) และในเวอร์ชันหลัง ๆ เพิ่มเช็คความกลม (`circularity = 4πA/P²`) เพื่อคัดเฉพาะรูปทรงกลม/รีแบบแตงโม ไม่ใช่วัตถุเหลี่ยม
4. **วัดขนาด**: ใช้ `minAreaRect` ครอบ contour ที่ใหญ่ที่สุด ได้ความกว้าง/สูงเป็นพิกเซล แล้วปรับให้นิ่งขึ้นด้วยค่าเฉลี่ยเคลื่อนที่แบบ exponential (`avg = 0.9*avg + 0.1*new`)
5. **แปลงหน่วย**: พิกเซล → เซนติเมตร โดยหารด้วย `pixel_per_cm` ที่ได้จากการปรับเทียบ
6. **ประมาณน้ำหนัก**: ใช้สูตรเชิงประจักษ์แบบทรงรี

   ```
   weight(kg) = 0.0019 * (2 * width_cm * height_cm^2 * π / 3) + 0.2228
   ```

7. **จัดเกรด** (เฉพาะ `GUI_card`):
   - น้ำหนัก > 3.0 กก. → เกรด A
   - น้ำหนัก 2.0–3.0 กก. → เกรด B
   - น้ำหนัก < 2.0 กก. → เกรด C
8. **บันทึกผล** (เฉพาะ `GUI_card`): เขียนลงตาราง SQLite `watermelon(id, width, height, weight, grade, timestamp)` พร้อมสรุปจำนวนต่อเกรดและส่งออกได้

## การปรับเทียบสเกล (Calibration) — มี 3 วิธีที่เคยลอง

| วิธี | อยู่ในโฟลเดอร์ | หลักการ |
|---|---|---|
| ค่าคงที่ | `compro/`, `GUI/` | กำหนด `pixel_per_cm = 25.5` ตายตัว (สันนิษฐาน: วัดจากระยะกล้อง-วัตถุคงที่ 60 ซม. ตามข้อความ "*** Keep 60 cm distance ***" ที่แสดงบนจอ) |
| ArUco marker | `GUI_ArUco/` | ใช้ marker เพื่อคำนวณ homography ปรับมุมมองกล้อง (ยังไม่ได้ตรวจสอบรายละเอียดการคำนวณสเกลเชิงลึกในไฟล์นี้) |
| ตรวจจับบัตรมาตรฐาน | `GUI_calibrate/`, `GUI_card/` | หา contour รูปสี่เหลี่ยม (`approxPolyDP` ได้ 4 มุม) ที่มีอัตราส่วนด้านยาว/สั้นอยู่ในช่วง 1.2–2.0 (ใกล้เคียงอัตราส่วนบัตร ISO/IEC 7810 ที่ ~1.586) แล้วคำนวณ `pixel_per_cm = pixel_width / 8.56` (8.56 ซม. คือความกว้างมาตรฐานของบัตรเครดิต/บัตรประชาชน) และปรับให้นิ่งด้วยค่าเฉลี่ยเคลื่อนที่เช่นกัน |

## สิ่งที่ต้องมีก่อน build (Requirements)

- **Qt 6** (โมดูล Widgets, Sql, LinguistTools) — build folder ระบุ `Desktop_Qt_6_10_2_MSVC2022_64bit`
- **OpenCV** (build จาก source เอง อยู่ในโฟลเดอร์ `opencv/`)
- **CMake** ≥ 3.16
- **MSVC 2022** (Windows) — โปรเจกต์อ้างอิง `cv::CAP_DSHOW` และ path แบบ Windows ตลอด จึงออกแบบมาให้รันบน Windows
- กล้องเว็บแคม

## วิธี build

1. เปิดไฟล์ `CMakeLists.txt` ของโฟลเดอร์ที่ต้องการ (เช่น `GUI_card/CMakeLists.txt`) ด้วย Qt Creator
2. เลือก kit `Desktop Qt 6.10.2 MSVC2022 64bit`
3. ตรวจสอบ/แก้ path `OpenCV_DIR` ใน `CMakeLists.txt` ให้ตรงกับตำแหน่งที่ build OpenCV ไว้จริงในเครื่อง (ปัจจุบัน hardcode เป็น `C:/project_compro/opencv/build`)
4. Configure แล้ว Build ตามปกติ

## จุดที่ควรระวัง / ปัญหาที่พบระหว่างตรวจโค้ด

- **`GUI_card/` ยังไม่สมบูรณ์ในตัวเอง**: `main.cpp` include และเรียกใช้ `CalibrationWindow` แต่ในโฟลเดอร์นี้ไม่มีไฟล์ `calibrationwindow.h/.cpp/.ui` และ `CMakeLists.txt` ของ `GUI_card` ก็ไม่ได้ผูก OpenCV/ไฟล์เหล่านี้ไว้เลย — build ตอนนี้จะ error แน่นอน คาดว่าต้องนำไฟล์ `calibrationwindow.*` (และการตั้งค่า OpenCV) จาก `GUI_calibrate/` มารวมกัน
- **Path OpenCV แบบ hardcode**: `OpenCV_DIR` ชี้ไปที่ `C:/project_compro/opencv/build` ตรง ๆ ทำให้ build บนเครื่องอื่นไม่ได้ถ้าไม่มี path เดียวกัน
- **สูตรน้ำหนักยังไม่ได้ระบุที่มา/การสอบเทียบ** ในโค้ด (เป็นสูตรเชิงประจักษ์ ควรมีข้อมูลชั่งจริงเทียบเพื่อยืนยันความแม่นยำ)
- **Git**: ทุกโฟลเดอร์ (`project_compro`, `GUI`, `GUI_ArUco`, `GUI_card`, `GUI_calibrate`) มีการทำ `git init` ไว้แต่ยังไม่มี commit และไม่มี remote — ยังไม่เคย push ขึ้นที่ใดเลย

## สรุปสถานะปัจจุบัน

โปรเจกต์อยู่ระหว่างพัฒนา/ทดลองแนวทางปรับเทียบสเกลหลายแบบขนานกัน (`GUI_ArUco` vs `GUI_calibrate`)
และเวอร์ชันล่าสุดที่มี feature ครบสุด (จัดเกรด + บันทึกฐานข้อมูล) คือ `GUI_card` ซึ่งยังต้องรวมส่วนปรับเทียบสเกลจาก `GUI_calibrate` เข้าไปให้ build ผ่านได้จริง
